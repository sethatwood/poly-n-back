<task type="auto">
  <name>Task 1: Run Tailwind upgrade tool and apply manual post-fixes</name>
  <files>package.json, package-lock.json, vite.config.js, src/style.css, tailwind.config.js, postcss.config.js, src/ConfigStart.vue, src/Stimulus.vue, src/App.vue, src/GameOverModal.vue, src/AchievementToast.vue, src/PauseModal.vue, src/GameHint.vue</files>
  <action>
    **Step 1: Capture pre-migration visual baseline**

    Start the dev server (`npm run dev`) and take note that it builds successfully. Stop it after confirming.

    **Step 2: Run the official Tailwind upgrade tool**

    Run `npx @tailwindcss/upgrade` from the project root. This tool will:
    - Update `tailwindcss` to 4.2+ and install `@tailwindcss/vite`
    - Add the tailwindcss() plugin to `vite.config.js`
    - Migrate `tailwind.config.js` theme config to `@theme` directives in `src/style.css`
    - Replace `@tailwind base/components/utilities` (or the equivalent `@import 'tailwindcss/base'` etc.) with `@import "tailwindcss"` in `src/style.css`
    - Rename affected utility classes in templates: `bg-gradient-to-r` to `bg-linear-to-r`, `shadow-sm` to `shadow-xs`, `backdrop-blur-sm` to `backdrop-blur-xs`, `outline-none` to `outline-hidden`, `ring` to `ring-3` (scale shift)
    - Delete `postcss.config.js` and `tailwind.config.js`

    **Step 3: Verify the upgrade tool results**

    After the tool runs, verify these specific outcomes:
    1. `tailwind.config.js` is deleted
    2. `postcss.config.js` is deleted
    3. `vite.config.js` imports `@tailwindcss/vite` and adds `tailwindcss()` to plugins
    4. `src/style.css` starts with `@import "tailwindcss"` (not the old three-directive pattern)
    5. `src/style.css` has `@theme` block with the `--font-sans` variable for Share Tech Mono
    6. `package.json` has `tailwindcss@^4` and `@tailwindcss/vite` in devDependencies

    **Step 4: Apply manual post-fixes the upgrade tool does NOT handle**

    These are documented pitfalls from research. Apply each fix:

    4a. **Ring opacity merging in ConfigStart.vue** (2 instances):
    - Find: `focus:ring-3 focus:ring-indigo-200 focus:ring-opacity-50` (the tool may have already renamed `ring` to `ring-3` but will NOT merge the opacity)
    - Replace the `focus:ring-opacity-50` class by changing `focus:ring-indigo-200` to `focus:ring-indigo-200/50` and removing `focus:ring-opacity-50` entirely
    - Result: `focus:ring-3 focus:ring-indigo-200/50`

    4b. **Ring opacity merging in Stimulus.vue** (1 instance, in a dynamic JS class binding):
    - This is inside a computed property or function returning class strings
    - Find the pattern `ring-2 ring-slate-600 ring-opacity-50` in the JS code
    - Replace with `ring-2 ring-slate-600/50` (remove `ring-opacity-50`, merge into color)

    4c. **Hover override for Capacitor touch devices in style.css**:
    - After the `@import "tailwindcss"` line and before `@theme`, add:
      ```css
      @custom-variant hover (&:hover);
      ```
    - This restores v3 hover behavior where hover applies universally, not just on hover-capable devices. Required because Capacitor's WKWebView/Android WebView reports as touch-primary.

    4d. **Button cursor override in style.css**:
    - Add a `@layer base` block:
      ```css
      @layer base {
        button:not(:disabled),
        [role="button"]:not(:disabled) {
          cursor: pointer;
        }
      }
      ```
    - TW4 changes button default cursor from `pointer` to `default`. This restores expected behavior.

    4e. **Verify dynamic class strings in App.vue**:
    - Read App.vue and check the `buttonClass()` and `feedbackClass()` functions (or similar dynamic class-building functions)
    - The upgrade tool may NOT have renamed classes inside JS string literals
    - If any of these patterns exist unrenamed in JS: `bg-gradient-to-*`, `shadow-sm` (meaning old v3 shadow-sm), `ring-opacity-*`, `backdrop-blur-sm`, `outline-none` -- apply the v4 equivalents manually
    - Expected renames: `bg-gradient-to-r` -> `bg-linear-to-r`, `shadow-sm` -> `shadow-xs`, `backdrop-blur-sm` -> `backdrop-blur-xs`, `outline-none` -> `outline-hidden`

    4f. **Verify dynamic class strings in Stimulus.vue**:
    - Same as 4e but for `shapeClass` and `cellClass` computed properties
    - Ensure any affected utility names inside JS strings are updated to v4 equivalents

    **Step 5: Verify the app builds and runs**

    Run `npm run dev` and confirm:
    1. Dev server starts without errors
    2. No Tailwind-related warnings in terminal output
    3. Run `npm run build` and confirm it succeeds with exit code 0

    **Step 6: Verify old files are gone**

    Confirm `tailwind.config.js` and `postcss.config.js` do not exist. If the upgrade tool left them, delete them manually.
