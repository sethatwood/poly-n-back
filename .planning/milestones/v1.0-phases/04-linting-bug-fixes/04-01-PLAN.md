<task type="auto">
  <name>Task 2: Fix division-by-zero, debounce guard, bounds check, and history cap in gameStore</name>
  <files>src/store/gameStore.js</files>
  <action>
Apply four surgical fixes to `src/store/gameStore.js`:

**FIX-01: Division by zero guards (4 sites)**

1. `finalScoreAccuracy` computed (around line 114-117): The guard on line 115 checks `potentialCorrectAnswers.value === 0` but the actual divisor on line 116 is `previousPotentialCorrectAnswers.value`. Fix: change the guard to check `previousPotentialCorrectAnswers.value === 0`.

2. `highScoreAccuracy` computed (around line 119-123): Already has a `highScorePotential === 0` guard — verify it works correctly. This one is already correct.

3. `respondToStimulus` line 300: `Math.round((score.value / previousPotentialCorrectAnswers.value) * 100)` — add guard: `const currentAccuracy = previousPotentialCorrectAnswers.value === 0 ? 0 : Math.round((score.value / previousPotentialCorrectAnswers.value) * 100);`

4. `respondToStimulus` line 301: `Math.round((highScoreData.value.score / highScoreData.value.potentialCorrectAnswers) * 100)` — add guard: `const hsAccuracy = highScoreData.value.potentialCorrectAnswers === 0 ? 0 : Math.round((highScoreData.value.score / highScoreData.value.potentialCorrectAnswers) * 100);`

**FIX-02: Bounds check verification**
The existing `nBackIndex >= 0` check on line 275 already guards array access. Verify that `respondedThisTurn.value[stimulusType] = true` (line 324) is inside the `if (nBackIndex >= 0)` block so it only marks as responded when the response was actually evaluated. Currently it is OUTSIDE the guard — move it inside so early-game taps don't mark buttons as responded without evaluation.

**FIX-03: Debounce guard**
Add at the very top of `respondToStimulus(stimulusType)` function, BEFORE the `nBackIndex` calculation:
```javascript
if (respondedThisTurn.value[stimulusType]) return;
```
Then move `respondedThisTurn.value[stimulusType] = true;` to immediately after the guard (before any game logic). This ensures:
- Rapid taps are blocked (guard at top)
- The button is marked as responded BEFORE processing (not after)
- The mark happens inside the function regardless of nBackIndex (early-game taps still disable the button)

**FIX-04: Stimulus history cap**
After `stimulusHistory.value.push({ ...currentStimulus.value });` on line 181, add:
```javascript
const maxHistory = nBack.value + 50;
if (stimulusHistory.value.length > maxHistory) {
  stimulusHistory.value = stimulusHistory.value.slice(-maxHistory);
}
```

After all fixes, run `npx eslint src/store/gameStore.js --fix` and `npx prettier --write src/store/gameStore.js` to ensure the file conforms to the new linting rules.
